## 应用介绍（可直接粘贴）

阅易是一款本地优先的电子书阅读器，为鸿蒙 PC 而来。

【格式全支持】EPUB / PDF / MOBI / AZW3 / FB2 / CBZ / TXT（含 GBK 编码），竖排、大文件、扫描件 PDF 均可流畅打开。

【阅读体验】深浅色主题随系统、字号字体行距全可调、翻页/滚动双模式、竖排排版，阅读进度与标注自动保存，重启不丢。

【标注与笔记】高亮、下划线、笔记、书签一应俱全，支持精确到段落的定位恢复。

【听书】内置 TTS 语音朗读，调用系统语音引擎，可后台连续朗读。

【开放同步】支持 KOReader 同步协议（自配服务器）、WebDAV 备份，数据自主掌控。

【隐私干净】不采集个人信息，匿名使用统计默认关闭；无广告、无推送、无内置书城。书籍内容全部由您从本地导入，本应用不分发任何内容。

基于开源电子书引擎（AGPL-3.0）移植，源代码公开：https://github.com/serendipityovo/readest

## 审核信息·五轮答复口径（TXT file-is-empty 终局 + 邮箱链接）

【关于「导入TXT后开始阅读提示 file is empty」——根因已在本轮彻底定位并修复】：经在本方环境完整复现审核路径（下载TXT→导入→开始阅读→同样报错 file is empty），定位到根因：TXT 导入时应用在内存中将 TXT 转换为 EPUB 后，通过流式分块写入通道落盘；该通道的数据块经跨层序列化为键值映射形态，本应用的原生桥接层此前按数组形态解析，静默解析为空——每一块均写入 0 字节，最终落盘文件为 0 字节。由于导入流程自身的元数据校验不依赖该文件内容，导入显示成功并正常创建书卡，而打开阅读时检测到文件为 0 字节即报 file is empty。v1.0.2/1000016 修复：①写入数据块解析改为形态归一（键值映射/数组/字符串/base64 全兼容）②增加零字节写入熔断（数据非空但解析为空时立即报错，不再静默落盘）③流式覆盖写补齐截断语义（防重复导入残留旧数据）。修复已在完整复现环境端到端验证：TXT 下载→导入→开始阅读→正文正常渲染分页。

【关于「邮箱注册，收到邮件后点击邮件内地址无法访问」】：应用的账户同步功能依赖上游开源项目的海外云端服务（Supabase），其邮件确认链接的域名在大陆网络环境下无法访问，属服务端可达性问题、客户端无法修复。为避免影响用户体验，v1.0.2/1000016 已移除邮箱登录/注册入口（该功能依赖上述海外服务），登录页保留华为账号登录（Account Kit）选项；应用全部阅读功能无需登录即可使用。

## 审核信息·TXT 打开失败说明（四轮答复口径）

【关于「导入TXT后开始阅读提示 file is empty」】：根因已定位并修复。技术说明：TXT 导入时应用先在内存中将 TXT 转换为 EPUB 再落盘，该写入通道使用的字节序列化格式（JSON 字节映射）在部分设备的 WebView 代理层存在兼容性差异，导致写入文件内容为空——导入流程本身校验通过（书卡正常创建），但打开时检测到文件为 0 字节即报错。【后续更正】该轮修复（base64 编码+落盘核验）作用于整文件写入通道，但经第五轮反馈与完整复现验证，实际故障路径为流式分块写入通道（详见下节五轮答复口径），故该轮修复未触及真因； 最终修复见 v1.0.2/1000016（流式数据块解析归一+零字节熔断），已在完整复现环境端到端验证。

## 审核信息·在线书库说明（三轮问题2 答复口径）

【关于「在线书库-热门目录-浏览 无法加载页面」】：根因为请求头构造缺陷（用户代理常量含非 ASCII 字符导致 Headers 构造抛错），v1.0.2/1000012 已修复：请求头还原为合法 ASCII 值、网络层固定 HTTP/1.1 规避部分网关的 HTTP2 帧层兼容问题。热门目录现收录 Project Gutenberg（www.gutenberg.org）与 Unglue.it 两个公共书源，均经大陆网络直连实测可达（HTTP 200）。书源加载与浏览功能已在 HarmonyOS PC 模拟器（API 6.1.0）实测：目录列表、Popular 分组、书籍详情均正常渲染。
